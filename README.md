# ShowFavicon (Windows)

A notification-area app that keeps one icon per configured site, drawn from that
site's favicon. Left click opens the site, right click opens a menu. There is no
main window: the tray icons *are* the app.

Windows port of the ShowFavicon idea (see `doc/plan-windows-11.md` for the
original plan and its reasoning). Pure C++ / Win32, no GUI toolkit, no runtime
dependencies.

## How this code was written

This project is **vibe coded**. Every line was generated by **GitHub Copilot**
(model **DeepSeek V4 Flash**) from prompts by Martin Oberzalek, who reviewed,
built and tested each change; nothing was typed by hand. The behaviour described
below was verified on the machine it was written on (Windows 11 25H2, build
26200) rather than audited for every edge case. Status: pre-1.0, no version
resource yet.

## What it does

- **One tray icon per site.** The host of each URL is the tooltip.
- **Icon discovery:** fetch the site, take every `<link rel="...icon...">` href
  in document order, fall back to `/favicon.ico` in the origin root, and use the
  first candidate that decodes. PNG/JPEG/BMP/GIF/ICO go through WIC, SVG through
  nanosvg. The result is cached as PNG under `icons\<host>.png`.
- **Offline is visible:** when a fetch fails and a cached icon exists, that icon
  is drawn grayed (55 % alpha) instead of disappearing.
- **Refresh:** hourly, plus immediately on a network address change, plus
  *Update now* in the menu. After a failure the retry backs off in 30 s steps
  (30/60/…/180 s) and gives up until the next trigger after six attempts.
- **Settings dialog** (right click → *Configure…*): add, edit (double click or
  *Edit*) and remove sites, drop `.url` files or URLs onto it, and a *Start with
  Windows* checkbox. A URL is reachability-tested before it is accepted: input
  that is not an http/https URL with a host is refused, a URL that is merely
  unreachable is kept with a warning.
- **One instance per session.** Starting it again asks the running instance for
  the settings dialog and exits; if the running instance is still shutting down,
  the new start waits for it instead of doing nothing.
- **First run:** nothing configured seeds `https://github.com/` and opens the
  settings dialog.

## Tray icons that stay visible

Windows 11 parks a new notification-area icon in the overflow flyout, and there
is no API to promote one. The shell stores the per-icon choice in
`HKCU\Control Panel\NotifyIconSettings\<hash>` as an `IsPromoted` DWORD — the
same value the *Settings → Personalisation → Taskbar → Other system tray icons*
page writes. ShowFavicon writes `IsPromoted = 1` for its own entries: once at
startup, then a few times on a timer, because the shell only records a brand new
icon a moment after it was added. A running shell applies the change
immediately, so no Explorer restart is needed.

If an icon ever does end up in the overflow anyway, turn it on once by hand in
that settings page; the choice sticks.

## Requirements

- Windows 10/11 (developed on Windows 11 25H2, build 26200).
- **MSYS2 with MinGW-w64**: `g++` 16 (C++23), Ninja, and `windres`.
  `scripts/install-msys2.ps1` installs the toolchain, or use the VS Code task
  *MSYS2 + MinGW-w64 installieren*.
- **CMake** ≥ 3.20.
- The **cpputils submodule**: `git submodule update --init --recursive`.
  It provides `CPPDEBUG`, `Tools::format`/`Tools::wformat` and the UTF-8
  helpers. It is never modified from here.
- Nothing at runtime: the binary is linked `-static -s`, and HTTP (WinHTTP),
  image decoding (WIC), graying (GDI+) and dialogs are all Windows components.

## Build

```powershell
git submodule update --init --recursive

# Release -> build\showfavicon.exe
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/build.ps1

# Debug   -> build-debug\showfavicon.exe
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/build-debug.ps1
```

In VS Code: *Build ShowFavicon (Release)* is the default build task,
*Build ShowFavicon (Debug)* the debug one, and F5 uses the launch configuration
*Debug ShowFavicon (GDB/MinGW-w64)* with `gdb.exe` from MSYS2.

Two notes:

- **A running instance locks the exe.** The link step then fails with
  `cannot open output file showfavicon.exe: Permission denied`. Stop the app
  first.
- **Release keeps the logging.** CMake's `-DNDEBUG` is stripped from
  `CMAKE_CXX_FLAGS_RELEASE`, because cpputils' `CPPDEBUG` is compiled out with
  it and a tray app's log matters most in the shipped binary. Note that this also
  keeps `assert()` live in Release.

## Run

```
showfavicon.exe        # tray only
showfavicon.exe -d     # also attach to (or allocate) a console and log there
```

Every message goes to the log file either way. The log is written by a
dedicated thread and flushed every 3 s, so the newest lines can lag a few
seconds behind the action.

## Files and registry keys

| Path | What |
|---|---|
| `%LOCALAPPDATA%\ShowFavicon\sites.txt` | one URL per line, UTF-8 |
| `%LOCALAPPDATA%\ShowFavicon\icons\<host>.png` | icon cache |
| `%LOCALAPPDATA%\ShowFavicon\icons\<host>.png.failed` | marker with the outcome of the last fetch, for inspection only |
| `%LOCALAPPDATA%\ShowFavicon\showfavicon.log` | the log |
| `HKCU\Software\Microsoft\Windows\CurrentVersion\Run\ShowFavicon` | autostart, written only by the checkbox |
| `HKCU\Control Panel\NotifyIconSettings\<hash>\IsPromoted` | keeps this executable's icons out of the overflow |

## How it works

- **Threads:** `main` (UI and tray), `worker` (fetch, decode, cache — one
  request at a time), `network` (`NotifyAddrChange`), `logger` (async log
  flushing). All named through `SetThreadDescription`, so they show up in a
  debugger.
- **`main.cpp`** — a hidden top-level window owns the tray icons, the tray menu,
  the promotion timer, the single-instance name and the message loop. The app
  has no visible window at all; quitting goes through *Exit* in the tray menu.
- **`icon.cpp`** — favicon discovery, WIC and nanosvg decoding, PNG cache,
  graying.
- **`http.cpp`** — WinHTTP `GET` with redirects followed by hand, so the final
  URL is known and relative icon hrefs resolve against it.
- **`settings.cpp`** — the settings dialog; **`util.cpp`** — URLs, UTF-8, the
  registry, the site list; **`logging.cpp`** — the async log session.
- **Logging:** `CPPDEBUG(...)` → cpputils → `AsyncOut::Debug`, which fans out to
  a console backend and a file backend (`src/AsyncOutDebug.*` and
  `src/AsyncFileLogger.*`, vendored from the reference project's `libcommon`).
